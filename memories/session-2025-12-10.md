## Session 2025-12-11 - Small ROI Detection Fix

### Problem
Image `AQUA7_51443_...jpg` had valid contour candidate at step 3.5 (visualization) but no detection at step 3.6.
The plate box `(219, 428, 128, 22)` with AR=5.82 was detected by contour but rejected during character validation.

### Root Cause Analysis
1. **Character validation too strict for small ROIs**: 
   - ROI height = 22px (very small)
   - `detect_character_candidates()` used `aspect_ratio_range=(0.1, 1.5)` which rejected wider characters
   - `max_height_ratio=0.9` (19.8px max) rejected components spanning ROI height (22px)
   - Result: 0 character candidates detected → score=0 → rejected as invalid

2. **OCR fails on small ROIs**:
   - Tesseract needs images ~50px+ height for reliable OCR
   - Small ROIs had low contrast

### Fixes Applied

#### 1. `src/lp_detector.py` - `detect_character_candidates()`
Added adaptive parameters for small ROIs (height < 50px):
```python
if h < 50:
    aspect_ratio_range = (0.1, 3.0)  # Allow wider characters
    max_height_ratio = 0.98  # Allow taller characters
    min_area_ratio = 0.002  # Allow smaller characters
```

#### 2. `src/pipeline.py` - `_process_detection()`
Added upscaling and CLAHE for small ROIs before OCR:
```python
MIN_HEIGHT_FOR_OCR = 50
if corrected.shape[0] < MIN_HEIGHT_FOR_OCR:
    scale_factor = MIN_HEIGHT_FOR_OCR / corrected.shape[0]
    corrected = cv2.resize(corrected, None, fx=scale_factor, fy=scale_factor, 
                           interpolation=cv2.INTER_CUBIC)

clahe = cv2.createCLAHE(clipLimit=2.5, tileGridSize=(8, 8))
corrected = clahe.apply(corrected)
```
